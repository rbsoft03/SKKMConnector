# SkkmConnector

`.NET`-библиотека (`net6.0`) для работы с **Сервером ККМ**
из приложений на C#. Даёт класс `ServerKkm`: свойства на вход, методы на
действие, свойства на выход - вместо ручных HTTP-запросов к серверу печати.

> Полный перечень операций, полей и значений - в документации API (см. [Полный API](#полный-api))

## Возможности

- **Полное покрытие REST API Сервера ККМ 4.0** — печать чеков, возвраты и коррекции,
  открытие и закрытие смены, X/Z-отчёты и отчёт о расчётах, внесение и выемка
  наличных, слипы, картинки, маркировка, фискализация, очередь печати, шаблоны,
  операции, а также администрирование (пользователи, настройки службы, пулы,
  добавление и изменение ККТ).
- **Простой доступ** — один объект `ServerKkm`: заполняете свойства, вызываете
  метод, читаете результат из свойств - без ручной сборки HTTP-запросов.
- **Синхронный и асинхронный режим** - ждать выполнение на кассе или поставить
  задание в очередь и опросить статус позже.
- **Состояние касс** - список устройств с сервера, сведения о ККТ, статус смены,
  счётчики, остаток наличных.

## Требования

- **.NET 6** (`net6.0`) - SDK для сборки, runtime для запуска приложения.
- **Windows** - на данный момент поддерживается только Windows.
- **Доступный Сервер ККМ 4.0** - адрес и порт службы печати; если на сервере
  выключен анонимный доступ - токен авторизации.

## Установка

Коннектор подключают двумя путями: **NuGet-пакетом** (обычная интеграция) или
**ссылкой на проект** (когда коннектор лежит рядом и правится вместе с приложением).
Код использования везде один: пространство имён `SkkmConnector` и класс `ServerKkm`.

### NuGet-пакет

Пакет `SkkmConnector` устанавливается локально из файла `.nupkg`. Сам файл можно
взять готовым или собрать из исходников - дальше установка одинаковая.

**Готовый пакет.** В репозитории уже лежит собранный `SkkmConnector.1.25.5.nupkg`.
Укажите папку с ним как источник NuGet и установите пакет в своё приложение:

```powershell
dotnet add package SkkmConnector --version 1.25.5 --source "C:\путь\к\папке-с-nupkg"
```

В `--source` указывается папка, где лежит файл `.nupkg`, а не путь к самому файлу.

Второй вариант - прописать папку-источник в файле `nuget.config` рядом с решением.
Тогда пакет будет виден и в командной строке, и в Visual Studio:

```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <add key="local-skkm" value="C:\путь\к\папке-с-nupkg" />
  </packageSources>
</configuration>
```

После установки в файле проекта появится ссылка на пакет:

```xml
<PackageReference Include="SkkmConnector" Version="1.25.5" />
```

**Собрать пакет самому.** Соберите и упакуйте библиотеку - получится тот же файл
`.nupkg`, который затем ставится способом выше:

```powershell
dotnet pack SkkmConnector\SkkmConnector.csproj -c Release -o "C:\путь\к\папке-с-nupkg"
```

### Ссылка на проект

Добавьте проект коннектора в своё решение и сошлитесь на него:

```powershell
dotnet add MyApp.csproj reference C:\путь\к\SkkmConnector\SkkmConnector.csproj
```

В файле проекта появится:

```xml
<ProjectReference Include="..\SkkmConnector\SkkmConnector.csproj" />
```

Для поставки клиенту обычно берут NuGet-пакет; для доработки самой библиотеки
удобнее ссылка на проект.

## Как открыть и собрать в Visual Studio 2022

### Шаг 1 — проверь версию Visual Studio 2022

Нужна любая редакция VS2022 (Community — бесплатная и достаточная). Если ещё не
установлена — скачай с [visualstudio.microsoft.com](https://visualstudio.microsoft.com/ru/downloads/).

Если VS2022 уже стоит — на всякий случай проверь обновления: **Справка → Проверить
наличие обновлений**.

### Шаг 2 — поставь workload

1. Открой **Visual Studio Installer**
2. Найди VS2022 → **"Изменить"**
3. Во вкладке **"Рабочие нагрузки"** поставь галку
   **".NET desktop development"** или **".NET cross-platform development"** —
   достаточно любого варианта с поддержкой .NET SDK

### Шаг 3 — проверь .NET 6 SDK

```powershell
dotnet --list-sdks
```

В списке должна быть строка с версией `6.0.x`. Если нет:

```powershell
winget install Microsoft.DotNet.SDK.6
```

### Шаг 4 — открой решение

Дважды кликни `SkkmConnector.sln`, либо **Файл → Открыть → Проект/решение**.

### Шаг 5 — восстанови NuGet и собери

Обычно восстановление происходит само при первой сборке. При необходимости:
**ПКМ на решении → "Восстановить пакеты NuGet"**.

`Ctrl+Shift+B` — собрать решение. Это библиотека: отдельного «запуска» нет —
подключай проект к своему приложению и запускай уже его.

### Частые проблемы

- **Ошибки про недостающие типы сразу после клонирования** — **Build → Clean
  Solution**, затем **Rebuild Solution**
- **"Restore failed"** — проверь интернет или очисти кэш:
  `dotnet nuget locals all --clear`, затем повтори восстановление

## Как устроен коннектор

Один экземпляр `ServerKkm` — одна рабочая сессия.

1. Задайте подключение: адрес, токен, имя кассы, кассира.
2. Перед новым чеком вызовите `NewRequest()` — очистятся позиции, оплаты,
   покупатель и коррекция. Подключение и кассир останутся.
3. Заполните свойства под операцию.
4. Вызовите метод.
5. Проверьте `Ok`, при ошибке читайте `ErrorCode` и `ErrorDescription`.

```csharp
if (!kkm.Ok)
    throw new InvalidOperationException($"{kkm.ErrorCode}: {kkm.ErrorDescription}");
```

Ограничения:

- объект не потокобезопасен — на параллельную работу создавайте отдельные экземпляры;
- коннектор не проверяет состав чека — неверные данные отвергнет сервер;
- после `Dispose()` экземпляр использовать нельзя.

## Использование

Схема работы одна для всех операций: **задать свойства → вызвать метод →
прочитать результат из свойств**.

### Подключение

| Свойство | По умолчанию | Назначение |
| --- | --- | --- |
| `Host` | `localhost` | Хост сервера ККМ (IP или DNS) |
| `Port` | `4398` | TCP-порт службы печати |
| `UseHttps` | `false` | Обращаться к серверу по HTTPS вместо HTTP |
| `Timeout` | `60 с` | Таймаут запроса к серверу |
| `Token` | пусто | Токен авторизации (заголовок `api_key`). Нужен, если на сервере выключен анонимный доступ |
| `AuthUserName` | `Admin` | Логин для `GetUserToken()` (Basic Auth) |
| `AuthPassword` | `Admin` | Пароль для `GetUserToken()` |
| `TerminalId` | пусто | Идентификатор рабочего места (заголовок `TerminalId`) |
| `DeviceName` | пусто | Имя кассы на сервере |
| `Cashier` | `null` | Кассир для документов |
| `QueueTaskId` | пусто | Id задания в очереди печати |
| `ShiftsFrom` / `ShiftsTo` | последние 7 дней | Период для списков отчётов, чеков и операций |

Токен берётся в веб-консоли сервера ККМ из профиля пользователя. `Ping` работает
и без токена. Хост, порт, токен и имя кассы можно менять между вызовами — один
экземпляр по очереди работает с разными ККТ. Прервать текущий запрос можно
методом `kkm.Cancel()`.

```csharp
await kkm.Ping();          // проверка связи
await kkm.GetDeviceList(); // список касс
await kkm.Connect();       // сведения по DeviceName
```

### Пример: печать чека прихода

```csharp
using SkkmConnector;

using var kkm = new ServerKkm
{
    Host = "localhost",
    Token = "<токен>",
    DeviceName = "Emu",
    Cashier = new Cashier { Name = "Иванов А.И." }
};

kkm.NewRequest();                          // сброс позиций, оплат, покупателя
kkm.PaymentType = 1;     // тип чека
kkm.TaxVariant  = 0;      // система налогообложения
kkm.Positions.Add(new FiscalLine { Name = "Кофе американо", Price = 150, Tax = "20" });
kkm.Payments = new Payments { Cash = 150 };

await kkm.PrintCheck();
if (!kkm.Ok)
    throw new InvalidOperationException($"{kkm.ErrorCode}: {kkm.ErrorDescription}");

Console.WriteLine($"ФП: {kkm.FiscalSign}, смена: {kkm.ShiftNumber}");
```

Остальные операции устроены так же: смена (`OpenShift`, `CloseShift`, `ReportX`),
возврат и коррекция (тот же `PrintCheck` / методы `PrintCheckCorrection105/120),
наличные (`CashIn`, `CashOut`), слип, картинки, маркировка.

## Полный API

Свойства, методы и перечисления коннектора повторяют REST API Сервера ККМ.

- **Справочник по коннектору:** [`API.md`](API.md) - методы, эндпоинты, входные модели,
  перечисления и свойства-результаты
- **Встроенная документация сервера:** `http://<адрес-сервера>:8888/Doc/ApiDescription`
- **Базовый путь вебсервиса:** `/PrintService/api/v4` (TCP-порт по умолчанию — `4398`)

Подсказки по каждому свойству и методу доступны из
XML-документации, поставляемой вместе с пакетом.
